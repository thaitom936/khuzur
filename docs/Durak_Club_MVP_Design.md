# Durak 棋牌 App 俱乐部系统 MVP 设计方案 V1.0

- 目标市场：哈萨克斯坦及中亚
- 平台：iOS / Android
- 定位：俱乐部社交、推广、排行榜与收益分成
- 原则：不影响普通自由匹配；首版不做俱乐部比赛、专属房间

## 1. 产品目标

俱乐部作为玩家社交组织和推广渠道。玩家加入俱乐部后可聊天、参与排行榜；俱乐部运营者维护社区，并按成员产生的合格充值净收入和广告净收入获取分成。

## 2. 用户角色

| 角色 | 权限 |
|---|---|
| 普通玩家 | 浏览俱乐部、申请加入、退出、聊天、查看榜单、分享 |
| 俱乐部管理员 | 编辑资料、发布公告、管理成员、禁言、删除违规消息、查看收益 |
| 平台管理员 | 审核俱乐部、处理举报、封禁、设置分成比例、审核结算 |

## 3. MVP 功能范围

1. 创建俱乐部：名称、头像、简介、创建者、状态。
2. 加入/退出：同一时间只能加入一个俱乐部；记录成员归属起止时间。
3. 俱乐部主页：资料、公告、人数、本周积分、排名、分享入口。
4. 俱乐部聊天：成员实时文字及 Emoji、历史消息、举报、屏蔽、禁言、删除消息。
5. 排行榜：俱乐部周榜和俱乐部内成员周榜，保留历史快照。
6. 分享：俱乐部专属 HTTPS 链接，支持 Telegram、WhatsApp 和系统分享；未安装用户可先打开落地页，安装后可重新点击链接加入。
7. 收益管理：成员充值净收入、有效广告净收入、分成、月度结算及调整。
8. 平台后台：俱乐部与内容治理、结算审核、分成配置。

**暂不开发：** 俱乐部比赛、俱乐部专属房间、私聊、语音、图片消息、现金牌局。

## 4. 页面结构

### 4.1 俱乐部发现页
- 俱乐部排行榜、搜索、俱乐部卡片（名称、头像、成员数、周积分）、创建入口。
- 未加入玩家可查看公开资料，但不能查看群聊内容。

### 4.2 俱乐部主页
- 顶部：头像、名称、简介、人数、周排名、分享按钮。
- 公告区域。
- 四个 Tab：主页 / 聊天 / 排行 / 成员。
- 管理员额外可见“管理”入口。

### 4.3 俱乐部聊天
- 文字、Emoji、时间戳、历史分页、消息状态。
- 管理员可置顶公告、禁言、删除违规消息。
- 玩家可举报消息及屏蔽用户；平台提供内容过滤和人工处置。

### 4.4 俱乐部管理
- 基本资料、成员管理、公告、聊天治理、收益统计和结算记录。
- 只有经平台核验并签订合作协议的运营者可启用现金分成。

## 5. 成员归属规则

1. 玩家通过俱乐部页面主动点击“加入”，后端确认后生效。
2. 每位玩家同一时间最多有一个有效俱乐部成员关系。
3. 退出后停止将后续收入归属给原俱乐部。
4. 可配置换俱乐部冷却期（建议初版 7 天），需在加入前明示。
5. 记录加入、退出、踢出和重新加入事件，保留审计日志。
6. 不要求邀请码；不依赖 App Store 跨安装传递邀请参数。

## 6. 排行榜规则

- 俱乐部周榜：每个俱乐部本周积分最高的前 50 名成员积分之和。
- 成员周榜：俱乐部内玩家按有效对局积分排名。
- 积分与充值、广告观看、佣金无关。
- 周期：按统一时区和周起止时间结算，榜单定期刷新，结束后生成快照。
- 异常对局、作弊或被撤销成绩应触发积分重算。
- 同分时可依次按有效胜场、达到积分时间排序，最终以服务端规则为准。

## 7. 收益分成

### 7.1 收益来源

| 来源 | 建议初始比例 | 计算基数 |
|---|---:|---|
| 游戏内合法数字商品充值 | 20% | 扣除适用平台费用、税费、退款、拒付等后的可分配净收入 |
| 广告 | 30% | 广告平台最终确认并可归属到成员的有效净收入 |
| 对局、活跃、邀请人数 | 0% | 不计佣金 |

上述比例为可调整的业务假设，不是市场事实。

### 7.2 计算与结算

`俱乐部佣金 = 合格充值净收入 × 充值分成比例 + 合格广告净收入 × 广告分成比例`

- 仅计算成员归属生效期间产生的合格收入。
- 充值应根据支付凭证、退款和平台财务报表核对；广告按平台确认数据和分摊规则入账。
- 每月出具结算单，允许退款、无效流量、拒付等跨期调整。
- 佣金需有待确认、已确认、已结算、已撤销状态，避免重复入账。
- 收益与俱乐部排行榜完全独立。

## 8. 技术设计

### 8.1 建议服务
- 俱乐部服务：创建、成员、角色、公告。
- 聊天服务：WebSocket、消息持久化、内容审核。
- 排行服务：消费对局结算事件、计算周积分、榜单快照。
- 收益服务：消费支付和广告确认事件、归属核算、结算账本。
- 管理后台：审核、举报、风控、结算配置。

### 8.2 核心数据表

| 表 | 关键字段 |
|---|---|
| `clubs` | id, name, owner_id, description, avatar_url, status, created_at |
| `club_memberships` | id, club_id, user_id, joined_at, left_at, status |
| `club_member_events` | id, club_id, user_id, action, occurred_at |
| `club_announcements` | id, club_id, author_id, content, pinned_at |
| `club_messages` | id, club_id, sender_id, content, created_at, deleted_at |
| `club_moderation_actions` | id, club_id, target_id, action, reason, expires_at |
| `player_weekly_scores` | user_id, week_id, score, valid_matches |
| `club_weekly_rankings` | club_id, week_id, score, rank, calculated_at |
| `revenue_events` | id, user_id, source_type, source_id, net_amount, occurred_at, status |
| `club_commission_ledger` | id, club_id, revenue_event_id, rate, amount, status |
| `club_settlements` | id, club_id, period, amount, status, settled_at |

约束：同一收入事件不可重复分佣；成员关系不得出现重叠的有效归属时间区间；所有收益计算可追溯至原始事件。

## 9. App Store 与运营合规

- 俱乐部聊天属于用户生成内容，提供内容过滤、举报、屏蔽、管理处置及联系渠道。
- iOS 游戏内数字商品交易遵守适用的 App Store 支付规则。
- 不以玩家输赢、现金下注或可兑换筹码作为佣金依据。
- 俱乐部现金分成需要单独核验合作方身份、税务、支付和目标国家法规。
- 不鼓励虚假广告展示或诱导异常广告观看；以广告平台确认的有效收入为准。
- 平台应明示隐私政策、成员归属与退出规则、结算和争议处理规则。

## 10. 开发优先级与验收

**P0**：俱乐部 CRUD、成员归属、俱乐部主页、文字群聊、消息举报/禁言、基础排行榜。

**P1**：分享落地页、排行榜快照、收益事件归属、佣金账本、管理员收益报表。

**P2**：结算审核、后台运营工具、精细化聊天风控和异常收入调整。

关键验收：
- 未加入玩家无法读取俱乐部私有聊天；被禁言成员无法发送消息。
- 用户不能同时有效归属两个俱乐部。
- 换俱乐部后收入按事件时间准确归属，不重复计算。
- 充值退款和无效广告收入能冲销对应佣金。
- 周榜计算可复现，历史快照可查询。
